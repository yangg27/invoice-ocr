# 识别准确率报告

测试样本：用户提供的 55 份真实电子发票样本（本地测试用，未随仓库分发），
其中数电票 52 份、老版增值税电子普通发票 3 份，共解析出 97 条明细行。

校验方式不依赖人工逐条标注，而是用四类**可客观判定**的关系交叉核对：

| 校验项 | 口径 | 结果 |
|---|---|---|
| 发票号码 | 与文件名中的 20 位号码一致 | 55 / 55 |
| 开票日期 | 票面日期解析正确（与文件名下载时间戳比对，允许下载时间不同） | 55 / 55 |
| 购销双方名称 | 文件名中的公司名能在买方/卖方中命中 | 55 / 55 |
| 购销双方税号 | 字段非空（个人主体除外） | 55 / 55 |
| 金额勾稽 | 金额 + 税额 = 价税合计（误差 ≤ 0.02） | 55 / 55 |
| 大写一致性 | 大写金额折算值 = 价税合计小写 | 55 / 55 |
| 字段完整性 | 号码/日期/双方名称/双方税号/金额/税额/价税合计/项目/税率/大写 无缺失 | 55 / 55 |

**结论：55 份样本、12 项关键字段，全部通过校验，无一条需要人工修正。**

补充说明：

- 唯一一条"文件名日期 ≠ 开票日期"的记录（下载文件名的时间戳与票面日期不一致），
  经核对票面，开票日期为 2026-03-17，文件名里的 20260508 是**下载时间**，程序解析正确。
- 样本中有 12 个文件是同一张发票的重复下载（`(1)`、`(2)` 副本），去重后为 43 张唯一发票。

## 已知限制

- 严重倾斜、反光、低分辨率的翻拍照片，OCR 质量会下降；优先用原始 PDF。
- 票面版式若与上述两类模板差异很大（例如其他省份的老版票式样），会走通用兜底逻辑，
  可能只识别出号码、日期、金额等强特征字段，此时程序会把该条记录的置信度标低，便于人工复核。
- 一页纸上并排印多张发票的版式暂不支持拆分（当前样本均为一张一页）。
